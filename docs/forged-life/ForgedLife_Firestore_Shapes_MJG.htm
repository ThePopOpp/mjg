FORGEDLIFE

Firestore shapes for the MJG integration

Users, churches and groups as they exist today, one sample of each, and the contact document we are adding for consent. Samples are made up; ids are the real formats. Project: Firebase, Firestore in native mode, Cloud Functions 2nd gen. Timestamps are Firestore timestamps and will be sent as ISO 8601 strings in events.

1. Users

users/{uid}  (profile, readable by any signed-in user)

The uid is the Firebase Auth uid (28 characters). This document carries no email and no phone by design: it is readable by every signed-in account for leaderboards and rosters. Contact details live in the self-only document in the next section. Fields marked app-only are not relevant to the integration and will not be sent.

Role in ForgedLife is not a field on the user. It is derived: he is an admin or a leader of a church when his uid is in that church's adminUIDs or leaderUIDs (section 2), and a group leader when he is a group's facilitatorUID (section 3). The event payload will carry the derived role.

users/{uid}/private/contact  (new, readable by the owner only)

Written by the app at sign-in (email, from Firebase Auth) and on the consent sheet (phone, consents). Only the owner and our Cloud Functions can read it. This is the source of the user fields in events.

Field

Type

Notes

email

string

Current sign-in email from Firebase Auth. Apple Hide My Email relays end in @privaterelay.appleid.com.

emailVerified

boolean

From Firebase Auth.

emailIsRelay

boolean

True for an Apple private relay address.

signInProvider

string

"password", "apple.com" or "google.com".

phone

string

E.164, optional, entered on the consent sheet.

authorConsents

map

Keyed by author id. { granted, at, version, text, requested[], sms: { granted, at, version, text } }

updatedAt

timestamp

      "at": "2026-11-17T02:15:30Z",

2. Churches

churches/{churchID}

The id is a short slug or a random 20-character id. The join code is not on this document and is never sent.

Field

Type

Notes

name

string

Up to 120 characters.

city, state

string

State is a two-letter code.

ein

string

Optional, ties the church to our public directory.

timezone

string

IANA zone, for example America/Phoenix.

adminUIDs

array of uid

Church admins. The event carries only admins who consented, as {uid, name, email}.

leaderUIDs

array of uid

Group leaders. Not sent.

license

map

{ status: "active" | "trial" | "frozen", expiresAt? }. Not sent.

logo

string

Optional data URL or Storage URL.

studyIDs

array

Optional allow-list of studies. Not sent.

archived

boolean

Optional.

createdAt, updatedAt

timestamp

 

 

Not on the church today: website, email, phone, street address, denomination, description. We can add website and description to the console later if Mike's site wants them; we will leave them out of events until then.

3. Groups

A study run has two layers. A campaign is the church's run of a study (the study, the start date, who it is for). A group is one leader's small group inside that run; groups are documents in our challenges collection. Events will send the group with the campaign's study and start date folded in.

campaigns/{campaignID}  (a church's run of a study)

Field

Type

Notes

string

The run's name.

gender

string

"male", "female" or "" (either).

boolean

Open to men outside the church.

joinMode

string

"pick" (members pick a group) or "assign" (the church places them).

4. How the event payloads map

Field

Type

Notes

user.uid, email, email_verified

 

users/{uid} id; private/contact email and emailVerified; plus email_is_relay.

user.name

 

displayName (one field).

user.phone

 

private/contact phone when given.

user.church_id, group_ids

 

churchID; the ids of groups where he is in participantUIDs.

user.role

 

"church_admin", "leader", "member" or "none", derived.

user.requested, consent

 

authorConsents.mjg.requested; { at, version, text }; sms_consent { at, version, text } when granted.

church.*

 

id, name, city, state, timezone, logo_url, admins (consented only), updated_at. Website, email, phone, address, denomination, description omitted until we collect them.

group.*

 

id, church_id, study_id, name, description, leader (consented only), audience (gender), meeting_weekday, meeting_hour, timezone (the church's), start_date, length_days, member_count, capacity, location, public (openToChurch), status, updated_at.
